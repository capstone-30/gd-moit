# 디자인 기준

## 공통 규칙

- 기존 파랑·밝은 바탕과 로컬 한국어 고딕을 사용한다. 값은 [토큰](../frontend/tokens.css), 스타일은 [globals.css](../frontend/app/globals.css), 폼은 [공통 컴포넌트](../frontend/app/components/client.tsx)가 원본이다.
- 모바일 한 열, 넓은 화면은 목록·상세 보조 영역. 큰 제목·짧은 안내·충분한 여백을 사용한다.
- 입력·주요 버튼 높이 52px 이상, 상시 라벨·키보드 포커스. 본문 대비 4.5:1 이상, 입력 경계·포커스 3:1 이상.
- 주요 행동은 파랑, 위험 행동은 오류색과 문구. 선택·오류를 색만으로 구분하지 않는다. 입력 경계는 `border`, 장식 구분선은 `rule` 토큰을 쓴다.
- 모션은 짧은 누름 효과만; 모션 감소 설정에서는 이동 효과를 끈다. 별도 폰트·디자인 라이브러리는 추가하지 않는다.

## 공통 시각 체계

- 불투명 Liquid Glass: 카드·메뉴·팝오버는 흰 단색 표면, 밝은 안쪽 가장자리와 두 단계의 은은한 그림자를 공유한다. 사진 위 종류·설명·상세 버튼도 불투명 표면으로 표시한다. 입력은 옅은 중립 표면과 명확한 경계, 선택은 브랜드색으로 구분한다. 그림자·사진 틴트·대화상자 바깥 배경만 투명도를 허용한다.
- 카드 곡률은 28px, 내부 입력은 18px, 메뉴는 32px로 통일한다. 주요 버튼은 브랜드색 채움과 약한 그림자, 보조 버튼은 흰 표면을 사용한다.

- 서비스 간 공통 셸은 상단 높이 76px(작은 화면 68px), 본문 시작 여백 32px(작은 화면 24px), 하단 메뉴 폭 최대 640px·높이 80px를 사용한다. 메뉴는 12px(넓은 화면 16px) 띄우고 기기 안전 영역을 반영한다. 메뉴바 형태는 gd-moit를 기준으로 통일한다. 메뉴바와 메뉴 강조 영역은 같은 `--radius-navigation`(32px)을 사용하고 hover·키보드 포커스에도 같은 윤곽을 적용한다. 아이콘은 24px, 아이콘과 문구 간격은 4px로 중앙 정렬하며 문구는 한 줄을 유지한다. 현재 메뉴는 배경·글자색·굵기로 구분하고 상단 표시선은 사용하지 않으며 키보드 포커스는 메뉴 안쪽에 표시한다.
- 입력은 흰 불투명 표면, 주요 버튼은 브랜드색·700 굵기, 보조 버튼은 흰 표면·얇은 경계를 사용한다. 입력 오류는 input·select·textarea에 동일하게 적용한다. 공통 규격 변경 시 상대 프로젝트의 토큰·공통 스타일도 함께 확인하며 기능별 카드 비율·동작은 유지한다.

- Liquid Glass에서 착안한 둥근 윤곽·부유하는 레이어를 사용하되 카드·입력·내비게이션 표면은 완전 불투명하게 처리한다. 배경 블러·투과·움직이는 반사광 없이 얇은 경계·상단 하이라이트·은은한 그림자로 깊이를 표현한다. 시간표·서류 등 밀도 높은 정보 영역에는 장식 그림자를 넣지 않는다.
- 두 서비스는 중립 회색 바탕·흰 표면·시스템 한국어 글꼴, 최대 1040px 콘텐츠 폭을 공유한다. 고유 강조색은 유지한다.
- 제목은 28~40px, 섹션 제목은 20px. 본문 16px·행간 1.65, 보조 설명 14px로 위계를 구분한다.
- 바깥 여백은 24px(작은 화면 20px), 패널 안쪽은 32px(작은 화면 20px). 입력은 부드러운 곡률, 버튼·필터는 캡슐, 패널은 큰 곡률을 사용하며 값은 토큰을 따른다. 입력·주요 버튼 높이는 52px 이상이다.
- 화면마다 주요 행동을 강조색 채움으로 표시하고 보조 행동은 중립 표면으로 구분한다. 현재 하단 메뉴는 배경·글자색·굵기로 구분하고, 그 외 선택 항목에는 표시선 또는 체크를 함께 쓴다.
- 입력 경계와 키보드 포커스는 3:1, 본문은 4.5:1 이상 대비를 유지한다. 메뉴·버튼 문구는 줄바꿈하지 않는다.
- 자동 등장 효과 없이 짧은 누름 반응만 사용하고 모션 감소 설정을 존중한다. 320·375·414·768px에서 가로 넘침과 조작 영역을 확인한다.

## 화면 구성

- 공통: 상단 브랜드 → 제목·설명 → 기능별 영역 → 로그인 계정 유형별 하단 고정 내비게이션. 내비게이션은 모바일에서도 화면 가장자리와 떨어진 불투명 캡슐로 표시한다. 하단 안전 영역과 본문 여백으로 콘텐츠·포커스가 메뉴에 가리지 않게 한다. 현재 메뉴는 아이콘·문구·배경·글자 굵기로 구분한다. 정상·로딩·빈 결과·실패·재시도·저장 전 이탈 상태를 제공한다.
- 목록: 열린 모임 카드가 중심이며 상단에 작은 유형 필터만 배치한다. 선택 즉시 적용하고 첫 페이지로 돌아간다. 시간에 따른 순서는 [FR-04](../spec.md#기능)를 따르며 낮은 강조의 카드도 본문 대비와 상세 링크를 유지한다. 현재 페이지 개수·장소·시간을 표시한다. 유형에 맞는 결과가 없으면 전체 보기, 전체 목록이 비었으면 개설 메뉴를 안내한다.
- 모임 카드는 은은한 유형 배지와 우측 상단의 채워진 원·빈 원으로 참여 인원을 표시하고 주제·장소·일정만 보여준다. 모집·시간 겹침 설명과 별도 상세 버튼은 생략하며 카드 전체를 상세 링크로 사용한다. 불투명 표면에 은은한 그림자로 깊이를 표현하고, 참여 불가·시간 비겹침은 흐린 표면과 약한 그림자로 구분하되 본문 대비·키보드 접근·상세 조회를 유지한다. 인원과 참여 상태는 보조 기술에도 전달한다. 대학 주관 모임은 서류 현황과 공지 대상 선택을 유지하며 선택 조작은 상세 이동과 분리한다. 목록은 카드당 최소 400px과 카드 사이 간격을 확보하면 두 열, 그보다 좁으면 한 열로 배치한다. 별도 목록 스크롤 영역 없이 페이지 전체를 위아래로 스크롤한다. 긴 제목·장소명은 줄바꿈한다.
- 담당자 주관 모임: 프로젝트 탐색과 소속 모임을 넓은 화면에서는 좌우, 모바일에서는 위아래로 배치한다. 현재 프로젝트는 표시선·체크로 구분한다. 등록 양식은 요청 시 펼치고, 모임별 입력을 세로형 카드로 구분한다. 공지 대상 선택은 카드 상단에 표시하며 좁은 결과 영역에서는 한 열을 유지한다.
- 시간표: 위쪽 요일·왼쪽 교시/시작·종료 시간 축으로 정렬하고 같은 시간을 칸마다 반복하지 않는다. 요일 전체 선택·해제와 개별 선택을 제공한다. 선택 상태는 체크와 색으로 구분하고 선택 교시 수를 표시한다. 좁은 화면은 시간 축을 고정한 표 내부 가로 스크롤로 조작 크기를 유지한다.
- 인증·개설: 좁은 폼·전체 너비 주요 버튼. 개설은 모임 카드와 같은 한 장의 카드에 유형 배지·인원 표시·제목·장소·일정을 배치한다. 유형 배지는 왼쪽, 인원은 오른쪽에 배치하며 표시 크기에 맞춘 선택 영역을 누르면 기본 선택 메뉴를 연다. 제목은 표시 위치에서 직접 입력하고 장소는 같은 행의 선택 목록에서 검증된 장소를 바로 선택한다. 일정은 미정으로 표시하고 누르면 팝오버로 참여 후 확정 흐름을 안내한다. 유형·인원 선택과 일정 안내는 카드 크기를 바꾸지 않는다. 카드 아래에 개설 버튼을 둔다. 인증은 이메일 → 인증번호의 현재 단계를 표시하고, 발송 후 이메일 요약·변경·남은 시간·재발송을 제공한다. 프로필·상세: 시간표·작업 섹션·펼치는 안전 메뉴.
- 프로필: 학교·이메일을 짧게 표시하고 `가능 시간 · 내 정보 · 차단 · 계정` 탭 아래에 선택한 기능 하나를 공통 카드 표면·곡률·여백으로 보여준다. 담당자 프로필에도 같은 카드를 적용한다. 선택 탭은 굵기와 밑줄로 구분하며 캐러셀·페이지 번호·별도 세로 스크롤 없이 페이지 전체를 스크롤한다. 입력 상태·직접 링크·키보드 이동을 유지하며 비활성 패널은 숨긴다. 시간표 불러오기는 접고 저장 버튼은 입력 아래에 둔다. 시간표 위에 저장·미저장·저장 중 상태를 표시한다. 내 정보는 동의 전 입력 불가 이유를 안내하고 관심 주제는 추가·개별 삭제 가능한 태그로 입력하며 작성 중인 주제도 함께 저장한다. 로그아웃과 펼치는 탈퇴 영역을 구분한다.
- 상세: 확정 상태 → 참여자 → 조율 → 코멘트. 참여 행동은 넓은 화면의 보조 영역, 작은 화면의 상태 바로 아래에 둔다. 개인정보는 항목·행간을 구분한다. 가짜 모임·운영값은 표시하지 않는다.
