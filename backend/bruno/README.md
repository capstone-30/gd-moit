# Bruno API 요청

Bruno의 **Open Collection**에서 이 폴더를 열고 `Local` 환경을 선택한다. 서버 실행은 [프로젝트 README](../../README.md#시작하기), 합성 계정 준비는 [로컬 로그인 데모](../../README.md#로컬-로그인-데모)를 따른다. 요청·스크립트 형식은 [Bruno 공식 문서](https://docs.usebruno.com/testing/script/javascript-reference)를 따른다.

## 로그인

1. `origin`을 서버의 `APP_ORIGIN`과 똑같이 설정한다. 기본값은 로컬 데모 주소이며 `baseUrl`은 이 주소의 `/api/v1`이다.
2. `01-auth`를 번호순으로 실행한다. `Configuration`은 학기·장소·교시·개인정보 고지 버전을, `Request OTP`는 인증 요청 ID와 데모 인증번호를 런타임 변수로 저장한다. 일반 메일 인증은 받은 번호를 환경의 `code`에 입력한 뒤 `Login`을 실행한다. 고지 내용 확인 후 로그인한다.
3. 로그인 직후 `Session CSRF`를 실행한다. 쿠키는 Bruno의 쿠키 저장·자동 전송을 켠 상태로 사용하며, CSRF 토큰은 런타임에만 보관한다.

계정 전환은 `07-account/Logout` → 환경의 `email` 변경 → `01-auth` 순서로 한다. 데모 학생·담당자 이메일은 로그인 데모 화면에서 확인한다. 개인정보·토큰·실제 계정은 공유 환경에 저장하지 않는다. 개인 환경이 필요하면 `Local.bru`를 `개인이름.local.bru`로 복사한다. 해당 파일은 Git에서 제외한다.

## 요청 실행

역할·참여 상태에 맞는 요청을 개별 실행한다. 계정 탈퇴·프로젝트 삭제·모임 삭제·참여 철회·신고 요청은 실제 데이터를 변경하므로 합성 데이터로 확인한다. 전체 컬렉션을 일괄 실행하지 않는다.

- 학생: `02-profile`, `03-meetings`, `04-safety`. 모임 생성 전 가능 시간을 저장한다. 다른 계정으로 참여할 때도 같은 `meetingId`를 지정한다.
- 담당자: `05-projects`의 프로젝트·모임 배정·공지, `06-hosted-meetings`의 공지·CSV·모임 삭제.
- 배정 학생: `06-hosted-meetings`의 상세·일정 조율·서류 제출·참여 철회. 제출 가능 상태와 필수 서류는 상세 응답을 확인한다.

생성한 모임·프로젝트 ID와 상세 응답의 ETag는 런타임 변수로 이어진다. 기존 데이터를 사용하려면 환경의 ID를 지정하고 해당 상세 요청을 먼저 실행한다. 런타임 값이 환경 값보다 우선하므로 생성한 ID를 바꾸려면 Bruno의 런타임 변수도 수정하거나 지운다.

`date`는 유효한 활동일로 직접 설정하고 `slot`은 해당 날짜의 요일에 맞는 교시를 선택한다. `userId`는 차단·강제 퇴장·CSV 대상 계정 ID다. 공지 수정·삭제의 `noticeId`와 `noticeVersion`은 프로젝트 공지 목록에서 가져온다. 삭제 요청은 본문 없이 전송하고 공지 삭제는 `If-Match`로 버전을 전달한다. 서류 부분 저장은 PATCH를 사용한다. `previousTitle`은 프로젝트 상세에서 저장한다. 목록의 다음 페이지는 응답의 `nextCursor`를 URL의 `cursor` 쿼리에 넣어 조회한다.

일정·수락·서류 수정 전에 상세를 다시 조회해 최신 ETag를 사용한다. 최초 서류 제출은 `If-Match`를 생략하고, 이후 제출은 본인 서류의 ETag를 전송한다. 인증·권한·충돌 응답 정책은 [HTTP 어댑터](../adapters/http/api.ts)가 원본이다.
